Privacy Policy

Last updated: 9 November 2026

In short: FD Cal is a browser-based fixed-deposit planning tool. Scenario inputs and calculations are processed in your browser. FD Cal does not operate an account service or send your scenario data to an FD Cal application server. Your draft is saved in this browser's local storage until you clear it.

1. Who operates FD Cal

FD Cal is an independent fixed-deposit calculator and portfolio simulator published at aaron-fredrick.github.io/FD-Calculator. It is not a bank, deposit-taking institution, broker, financial adviser or tax adviser. For privacy questions or requests, use the project's GitHub contact and issue page. Do not post account numbers, balances, personal identifiers or other confidential information in a public issue.

2. Information you enter

You may enter bank-account labels, balances allocated to a plan, deposit dates, cash inflows and outflows, strategy settings and other scenario assumptions. These values are used by the browser application to validate and calculate the scenario. They are not submitted to an FD Cal backend, uploaded to the repository, or transmitted to an analytics service by the current application.

Calculations run locally in your browser, including in an application-owned Web Worker. The worker receives the scenario data from the page within the same browser session; it is not a remote processing service. Bank catalogue CSV files are fetched as static application assets. Those requests do not include your scenario inputs.

3. Browser storage and retention

  • Saved scenario draft: FD Cal stores the current configuration in browser local storage under the key fd-cal:draft:v1. It remains in that browser profile until you use “Clear saved draft”, clear the site's browser storage, or the browser removes it. There is no automatic expiry implemented by FD Cal.
  • Privacy preferences: your necessary-storage and optional-analytics preference is stored in local storage under fd-cal:privacy-preferences:v1 until you change it or clear site storage. The preference is used to avoid showing the initial banner again after a choice has been saved.
  • In-memory state: active form values, calculation state and results remain in the page's memory while the page is open. They are normally discarded when the page is closed or reloaded, except for the saved draft described above.
  • Temporary report URL: when you open or download a generated report, the browser may create a temporary Blob URL. The application revokes that URL after the download/open action; the downloaded report file is under your control.

Static application files and bank catalogue responses may also be cached by your browser or delivery infrastructure according to the hosting response headers. FD Cal does not use that cache to store scenario inputs; browser and hosting cache retention is controlled by those systems rather than by a separate FD Cal expiry setting.

Use “Clear saved draft” to remove the saved scenario key. This does not erase downloaded reports, exported JSON files, browser history, backups, or the currently displayed form values. Clear those separately using your browser or file manager.

4. Reports and exported files

FD Cal generates the standalone HTML report in your browser from the scenario and calculation result. It is not uploaded by FD Cal. The report can contain the account labels and balances, cash-flow details, assumptions, simulated bookings and other information included in your scenario. Exported JSON configuration files can contain the same input data. Store, share and delete these files carefully; anyone with access to a copy may be able to read its contents. The report is designed to work offline and does not need a remote report-generation service.

5. Cookies, local storage and analytics

The current FD Cal application does not intentionally set its own cookies, and no analytics, advertising, tracking-pixel or session-replay provider is currently integrated. It uses browser local storage for the saved draft and privacy preferences. The preference interface groups this under “strictly necessary storage”; that setting is always enabled because the current application relies on this browser storage.

The optional analytics switch only records your preference in this browser. Selecting it does not activate analytics, create an analytics cookie, or send usage data today. If analytics is introduced later, FD Cal should identify the provider, explain the data collected and update this policy before enabling it. The saved preference is intended to be respected before any optional analytics storage or requests are activated.

You can change your choice at any time using “Cookie & storage preferences” in the application footer. If you clear site storage, the saved preference is also removed and the banner may appear again.

6. Hosting and third-party services

The application is hosted as a static website using GitHub Pages. When you access the site, GitHub and the network providers involved in delivering it may receive ordinary connection and request information, such as IP address, requested URL, timestamp, browser/user-agent information and security or diagnostic logs. These are hosting-layer operations outside FD Cal's application storage; FD Cal does not control GitHub's retention or processing. Review GitHub's Privacy Statement for its practices.

Links to bank websites, GitHub, documentation or other external sites take you away from FD Cal. Those sites have their own privacy practices. FD Cal does not control their content, cookies or data handling.

7. Data sharing and sale

FD Cal does not sell your scenario information and the current application does not share scenario inputs with advertisers or analytics providers. This statement does not cover data that GitHub or your internet service providers process to deliver network access, or information you choose to disclose directly to a third-party site or in a public support request.

8. Security

Local processing reduces the need to transmit financial scenario details, but it does not make your device or browser storage immune to compromise. Anyone who can use your unlocked device or browser profile may be able to access the saved draft and generated files. Keep your browser and device updated, use device access controls, and avoid entering real account credentials or unnecessary identifying information.

9. Your choices and rights

You can edit or clear the saved draft, change privacy preferences, delete exported files and use browser controls to clear site storage. Depending on your location, applicable data-protection law may provide additional rights. Because the current application does not maintain an FD Cal user account or receive scenario data, we may not hold a server-side copy that can be retrieved or deleted on request. Hosting-provider records are subject to the provider's own processes.

10. Children

FD Cal is a general-purpose financial calculation tool and is not designed to collect personal information from children. Do not enter personal information about another person unless you have an appropriate basis to do so.

11. Changes to this policy

This policy may be updated when the application, hosting or data practices change. The “Last updated” date above indicates the latest published revision. Material changes to analytics or other optional tracking should be reflected here before those features are enabled.

12. Contact

For questions about this policy, contact the project through the FD Calculator GitHub repository. Use a private communication channel for any information that should not be public; GitHub issues in this public repository may be visible to anyone.
